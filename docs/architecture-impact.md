# Architecture impact — every measured finding, and what it changed

**Date: 2026-07-25 (#527).** Population: every check registered in `tools/vendor-verify/verify.py`.
Recomputed by `pixi run audit-completeness`, which fails if a check has no row here.

This is step 5 of the audit chain: *what has reality changed for the architecture?* The answer is
only checkable if the question is asked of **every** measurement, including the ones that changed
nothing — otherwise "I considered the findings" is an assertion. A `no impact` row is a real
disposition and the commonest correct one: most of these confirm something the design already
assumed, and a confirmation is worth exactly as much as it costs to re-run.

Read alongside [`decision-audit.md`](decision-audit.md), which does the same over decision records.
This table runs the other direction: from measurement to design.

Forced [0029](decisions/0029-the-gate-is-three-mechanisms.md); made a `PreToolUse` hook mandatory on every worker; moved gate work from M28 into M26; flipped journey J6 from Partial to **Fails**. | `gate.hook-exit-2-beats-allow` | a hook exiting 2 blocks despite an allow rule | The enforcement point 0029 rests on. Without it the hook is advisory and nothing covers vendor tools. |
| `agy.adapters-own-flag-set-still-gates` | the same question on agy, whose hook rides `.agents/hooks.json` under `--add-dir` rather than `--settings` | **Stops the gate story being claude-only without saying so.** Every other gate measurement behind #703/#549/#550 ran claude, while the invariant is written about "a vendor CLI worker" — the `claim-scope` gate's exact failure, in the PR that cites it. It matters more here than on claude: `agy.permissions-are-global-only` makes the hook agy's *only* project-scoped gate, so nothing sits behind it. Its first run also exposed a confound in the check rather than a product defect — an escape target under `%AER_ARTIFACTS_ROOT%` is inside a directory the vendor was explicitly granted. |
| `gate.adapters-own-flag-set-still-gates` | a write escaping the outbox is blocked under the argv `ClaudeWorkerAdapter` really builds | **Closes the loop every prior gate finding was found outside.** `--bare` (#521), its two documented siblings, and environment inheritance (#549) were each found by READING, because nothing ran AER's own assembled flag set past the vendor. Verified discriminating: suppressing `--settings` in `Resolve` turns it red, with the write landing outside the outbox. |
| `agy.hook-command-survives-a-metacharacter-in-its-path` | which command-string forms let an agy hook handler actually start — a plain path, and one containing a space, `$` or `%` | **Found that AER's mandatory gate had never fired on agy at all (#706).** The adapter shipped `dotnet "<path>" agy-hook-check`; agy does not strip double quotes, so the handler never resolved, produced no stdout, and `agy.hook-malformed-stdout-fails-open` reads that as an **allow** — decision 0029's mandatory hook absent from every agy worker, silently, while six `agy.*` hook checks passed. All six wrote their handler command *unquoted*, so none exercised production's form: `claim-scope` from the inside. Four escaping forms were then measured against a spaced path and only single quotes carry one, which is now what ships. Pins a vendor behaviour AER cannot control and would not otherwise notice changing. |
| `agy.hook-deny-holds-under-the-mode-production-uses` | an agy hook deny still blocks under `--mode accept-edits`, the flag production defaults to | **Retires a cross-mode inference 0029 forbids.** Every other agy hook arm ran `--dangerously-skip-permissions`, which production reaches only when shell *and* network are both granted — so the gate's behaviour under the mode it normally runs in was assumed, on a vendor where `agy.force-ask-defeated-by-skip` is direct evidence that hook-verdict semantics *change* between skip and non-skip modes. Measured: it blocks under both, with the skip arm as the control. |
| `gate.simple-mode-override-restores-the-hook` | `CLAUDE_CODE_SIMPLE=0` fires the hook; an inherited `=1` kills the run at `Not logged in` rather than ungating it | **Retired an admission that was load-bearing.** `ClaudeWorkerAdapter`'s override was shipped as "best-effort, not a measured sentinel", its value chosen by analogy to a sibling variable — so 0029's mandatory hook rested on an unproven parse. Now measured. It also **corrected the hazard's shape**: an inherited `=1` fails loudly on a subscription host instead of producing a silent ungated worker, which is the opposite of what #549's threat model assumed. Scoped to subscription auth; an API-key host is unmeasured and is where the quiet failure could still live. |
| `gate.broken-hook-fails-open` | a hook that cannot execute lets the tool run, and the CLI reports nothing | **Turned 0029's startup self-check from prudence into a requirement**, and fixed what it must assert: a side effect the hook produced, per worker spawn. Also corrected the *cause* AER expected — CRLF and spaces in paths survive, so the vendor's documented Git Bash failure mode is not the one that bites, and the obvious mitigation would have prevented nothing. Closes #530. |
| `gate.hook-ask-in-auto` | a hook's `ask` forces a prompt even in `auto` | **Softened a conclusion 0015 had already drawn.** 0015 said an operator's `auto` leaves AER with no permission surface; the hook is the recovery path, so the surface survives a mode AER does not control. |
| `gate.elicitation-capability` | uncircumventable on claude across all three modes | Portable refusal primitive. With the agy arm, it is the only gate primitive measured unbypassable on both vendors. |
| `agy.elicitation-capability` | uncircumventable on agy under skip-permissions | **Turned an inference into a measurement.** Without it 0029's portability row would have been "assumed" — and `agy.force-ask-defeated-by-skip` shows that exact inference failing for the neighbouring mechanism. |
| `agy.url-mode-elicitation` | agy declares and routes SEP-1036 `mode: "url"` | The non-blocking durable gate is **already standardized**, and exists on one vendor. Added 0029's "build it to migrate" clause: releasing the call must be the normal path, not the crash path. |

| `gate.add-dir-loads-no-config` | `--add-dir` grants files, loads no config | Launch constraint: AER must control the worker's cwd or pass `--settings`. Lands in M26, not M28. |
| `gate.permission-request-not-headless` | `PermissionRequest` never fires under `-p` | Removed 0018's assumed notification source. Forced [0030](decisions/0030-aer-is-its-own-notifier.md). |

For AER's own gate the event is redundant: AER *is* the server and holds the pause already. It would matter for a pause AER did not author, but whether a third-party server can even be loaded alongside `--mcp-config` is unresolved (the run's server list did not read, and `None` is recorded as not-observed rather than folded into "zero servers"). The stderr pin in `OutcomeClassifierTests` is unaffected: it pins what AER must surface, not why agy said it. |

Sentinel: if agy ever starts resolving the conflict silently, a UI keeping them in sync would be over-constrained with nothing to say so. This also narrowed the register's older "accepts both together" reading, which had been generalised from an agreeing pair. |

On agy the question is different rather than answered: no event is session-level and `PreInvocation` cannot stop the call it precedes, but `injectSteps` may carry a `toolCall`, and the one measurement that looks like it closes that route does not record which step kind it injected. With `PermissionRequest` and `Notification`, that is the whole permission-notification surface confirmed absent headless, which is why 0030 says AER *is* the notifier rather than a listener. |

## agy

| check | result | architectural impact |
|---|---|---|
| `agy.permissions-are-global-only` | no project-scoped permission rules are honoured | **Hooks are agy's only per-worker gate.** AER cannot scope an agy worker's permissions without writing the operator's own settings file — which it must not. Makes 0029's mandatory hook load-bearing on agy specifically. |
| `agy.force-ask-defeated-by-skip` | `force_ask` collapses under `--dangerously-skip-permissions` | A vendor asymmetry running the *opposite* way from the usual one. It is also the evidence that made measuring agy elicitation non-optional rather than a formality. |
| `agy.hook-deny-honoured` | a `PreToolUse` deny blocks the call | Confirms the gate is symmetric across vendors at the hook layer — the premise 0029's mechanism table depends on, which rests on the deny being *honoured*, not on its reason reaching output. **Corrected:** this row and the check's own description previously read "and surfaces its reason". `agy.broken-hook-fails-open` measured that token absent from agy's output under `-p`, and the check never gated its PASS on it — so a green check was certifying a false half-claim. Scoped to what it tests. |
| `agy.broken-hook-fails-open` | agy also fails open; whether it does so *silently* is unmeasured | **Closed a generalisation, not a gap.** 0029's mandatory self-check was justified from a claude-only measurement while the sentence it supports — "the workspace hook is the only per-worker gate on agy" — is an agy claim. It now rests on an agy run. The consequence is worse here than on claude by exactly the asymmetry `agy.permissions-are-global-only` names: a dead hook on claude still leaves the MCP callback and elicitation; on agy it leaves nothing. The silence half is **not** claimed — no arm gave the output detector a positive control on agy — and the design does not need it, since claude's measured silence already requires the self-check AER runs on every worker. |
| `agy.fails-closed-headless` | `agy -p` auto-denies an ungated tool and names the rule | **No impact** — confirms 0015's corrected premise that both vendors fail closed. Also the reason a permissive arm is required to measure anything else about agy headless. |
| `agy.plan-mode-does-not-deny-writes` | agy writes files under `--mode plan` with no prompt and no refusal, both inside an `--add-dir` path and outside every directory it was given | **Withdrew a generalisation that two doc sites rested on, and exposed a second gap.** `agy.fails-closed-headless` measured one tool — a shell command — and the adapter's paragraph read it as "any tool needing a permission it cannot prompt for", across three modes (gate `claim-scope`). Neither `--mode` nor `--add-dir` bounds a write, so AER's own hook is the only gate on an agy worker's writes, which makes 0029's mandatory hook load-bearing here for the same reason `agy.permissions-are-global-only` already made it. The outside-`--add-dir` arm is the new part and it gates this check's verdict rather than sitting in prose: with a granted write neither hook consults the path at all, so nothing bounds where it lands — filed as #679 rather than patched, because the fix overlaps #669's workspace provisioning. |
| `agy.hook-payload-carries-write-path` | an agy `PreToolUse` payload for `write_to_file` carries `toolCall.args.TargetFile` naming the **absolute** target | **Decides whether #679's fix has an agy half at all.** `AgyHookCheckCommand` decides on `toolCall.name` alone, so confining a granted write to `WorkingDirectory ∪ AER_OUTPUT_DIR` depends entirely on the payload naming a path the hook can resolve — and `agy.plan-mode-does-not-deny-writes` already established that nothing agy offers bounds a write, leaving AER's hook as the only candidate. Measured rather than read off `agy__hooks.md`, because this file records two places that same documentation is wrong (`--cwd` documented and absent, `modelName` present and undocumented), and `agy.hook-env-inherited` only ever reported `toolCall.name` for `run_command` — a different tool, a different field. The absolute form is the load-bearing half: `OutboxPath` will not resolve a relative candidate against the hook's inherited cwd, and agy ignores the process cwd anyway (#472), so a basename would have left nothing to compare against. **Scoped to one of the four `WriteTools`** — the other three are unmeasured, which is why the gate denies a write whose path it cannot find rather than allowing it. Not a sentinel **on the condition that the hook denies when it cannot find a path** — that makes a vendor change loud rather than silent, and the reasoning is void if anyone writes it to allow-on-missing-path. |
| `agy.settings-allow-honoured-headless` | `permissions.allow` is honoured under `-p` | **No impact, and deliberately kept red-adjacent**: upstream #548 says otherwise and does not reproduce here. The check exists to notice if the upstream report becomes true on this host. |
| `agy.termination-behavior` | `PostInvocation terminationBehavior: terminate` ends the loop | Confirms agy's control surface is real and CLI-reachable. **No design change**; AER does not currently need it. |
| `agy.hooks-load-from-add-dir-not-only-cwd` | agy loads `.agents/hooks.json` from an `--add-dir` directory that is **not** the cwd; hooks in the cwd load **nothing** | **The claim #554's entire gate rests on, and it was fabricated before it was measured.** The adapter cited a check name — `agy.add-dir-grants-files-not-config` — that does not exist; the real neighbouring check, `gate.add-dir-loads-no-config`, is claude-scoped and runs the *opposite* way (`--add-dir` loads no hooks config there). Every other agy hook arm ran `--add-dir wd` with `cwd=wd`, so none could tell "loaded because --add-dir named it" from "loaded because it was the cwd" — while production always has them differ. Measured with three arms: production's arrangement loads and blocks; the cwd-only arm loaded nothing and ran ungated. Had it gone the other way, every agy worker AER spawns would have carried no gate at all, failing open and silent. Sentinel because that failure is invisible from inside AER. |
| `agy.hook-env-inherited` | an agy hook subprocess inherits the environment agy was spawned with | **Makes #554's gate implementable at all.** #543 ships one static settings file per vendor and sends the per-invocation denied-tool list through `AER_HOOK_DENIED_TOOLS`; that only works if the hook process inherits it. claude's corpus states inheritance explicitly, agy's says nothing, so the design could not reuse claude's answer (gate `claim-scope`). Sentinel: losing this fails **silently and totally** — an empty denied list reads as "nothing withheld", every tool is allowed, and the result is indistinguishable from a working gate. |
| `agy.hook-malformed-stdout-fails-open` | unparseable and **empty** hook stdout ALLOW; an unrecognised `decision` *value* DENIES | **Determined `AgyHookCheckCommand`'s failure posture, opposite to its claude sibling.** `HookCheckCommand` used to fail open, argued as "no worse than `--disallowedTools`, which covers the same names"; `agy.permissions-are-global-only` means agy has no such backstop, so anything this hook lets through is ungated outright. **Both now fail closed** — #649 moved the write tools off `--disallowedTools` so the outbox exemption could be reached, which voided the claude-side argument and left the two vendors' postures the same. The asymmetry is the actionable part: a crash, an exception trace, or a silent exit is an **allow**, while a merely wrong verdict string is safe — so the command must emit syntactically valid JSON on every path including its own catch-all handler. Not a sentinel: that conclusion holds whichever way a future agy resolves this, so nothing built on it can rot. |
| `agy.hooks-json-cached-at-startup` | agy reads `.agents/hooks.json` once at startup | **Downgraded a suspected gate bypass to a hygiene concern.** #554 must load its hook from an `--add-dir` directory, and `--add-dir` also grants the worker *write* access there — so the worker can reach the file that gates it. Because agy caches at startup, deleting or rewriting it mid-run does not disable the gate, and `EnsureAgyWorkspace` rewriting on every resolve stops a tampered file surviving into the next spawn **of AER's own hook file**. Scoped deliberately: production also `--add-dir`s the artifacts root and the room's working directory, which AER does not rewrite, and agy's docs place hooks in "`.agents/` in your workspace" — whether agy loads hooks from more than one workspace root, and which handler wins, is unmeasured. Not a claimed bypass; an unclaimed one. Sentinel: an agy that began re-reading per call would silently convert this into a real bypass, with nothing in AER's logs showing a difference. |

## What this table cannot tell you

- **Whether an implication is correct** — only that one was recorded and is traceable to a run.
- **Whether a finding that changed nothing should have.** A `no impact` row is a judgement. The
  defence is that each names *what* it confirms, so a wrong call is visible rather than silent.
- **What was never measured.** The blind spot is the unrun check, not the unrecorded row. The
  standing ones are listed under *Still not settled* in
  [`vendor-doc-audit.md`](vendor-doc-audit.md); the highest-value is now #531, whether a live
  SEP-1036 url-mode elicitation actually reaches a person and resumes, because it is the only
  finding here that needs a human rather than a better instrument.
- **Whether a result on one vendor holds on the other.** Nothing in this table enforces that, and
  two rows exist only because the question got asked late: `agy.elicitation-capability` and
  `agy.broken-hook-fails-open` were each written after noticing that a claude measurement was
  carrying an agy sentence. `agy.force-ask-defeated-by-skip` is the standing proof that the
  inference is unsafe — the same mechanism, opposite behaviour.
